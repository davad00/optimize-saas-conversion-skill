# Integration entry-page brief

Template: `TMP-018` · Category: `acquisition`

## Use when

Convert integration interest by showing the supported workflow and required setup.

## Required inputs

- Actual integration behavior and permissions
- Supported plans and external dependencies
- Sample input and output
- Known restrictions and setup effort

## Page scaffold

**Headline:** “[Supported action] between [system A] and [system B].”
**Workflow:** [Trigger] → [Product action] → [Destination result].
**Show:** [Real or explicitly illustrative input/output with source].

| Requirement | Supported scope | Buyer action | Cost or permission consequence |
| --- | --- | --- | --- |
| [Version/account type] | [Exact support] | [Connect/enable] | [Required subscription or access] |

**Setup path:** [Steps, required role, realistic effort].
**Limitations:** [Sync direction, fields, frequency, historical data, unsupported cases].
**Action:** [Connect available integration / inspect setup / request accurate assistance].

Do not equate an API, export, or roadmap item with a maintained native integration. Carry the selected workflow into onboarding where supported, while requesting only the permissions needed for that task.

**Verification:** [Connection, sample transfer, error, disconnect].

## Completion check

Confirm integration claims against current behavior, identify all paid dependencies, and verify the destination action works for the advertised account type.
